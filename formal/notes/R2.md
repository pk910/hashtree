### Architectural findings for the remaining multi-lane work

1. **The multi-lane kernels never return for `c ≥ width`; they tail-call the next kernel down.**
   x4's only `ret` is the count-0 path at pc 3. For `c ≥ 1` it ends at `jmpTail
   hashtree_sha256_avx_x1` (pc 4143); x8 tails x4, x16 tails x8.  The real C API
   (`src/hashtree.c`) dispatches on CPU features only and `src/test.c` calls e.g. x4 with
   counts 8 and 6, so the tail calls are part of the contract for arbitrary counts.
   `KSpec` requires `fin.tail = none` and runs one program, so no `KSpec` for x4/x8/x16 can
   hold for arbitrary `c`: the wrapper model needs a tail-following chain with a per-member
   `ro` region and a memory holding every member's rodata.
2. **Each object's `.rodata` overlaps the others and is not the linked layout.** Object-local
   read offsets: x4 = {0, 1024, 2048, 2176}, x8 = {0, 2048, 4096, 4352},
   x16 = {0, 4096, 4160, 8256, 8768, 8832, 8896, 8960}, x1 = {0, 256, 288, 544, 560, 576},
   shani = {0, 256, 272, 288, 304}. They collide at 0 (x4's is a 4-way broadcast K table, x1's
   the scalar K table), so one region-4 memory cannot serve two chain members, and x1 reads
   rodata even at count 0.  `run` already takes `ro`; the proof side must generalize
   `mem0sW`/`WfMemW`/`mem0RelW_of_wf` (currently hardcoded to region 4) and re-elaborate the
   chain members' slice checks at their own regions (the cut states in the generated proofs
   also contain the region number literally, e.g. `K1.gpr[1] = .ptr ⟨4,0⟩`).
3. **The x4 body uses the 408-byte stack frame.** The `entryS 24` layout of the fixed-count
   pilots and the `entryW` layout (return marker at `σ 9`) differ by the shift `σ 9 − 24`;
   all stack addresses shift uniformly, but the pilot's proofs are stated at `entryS 24`
   with `mem0s 4 rodata 24`, while a `KSpec` starts from `entryW` with `mem0sW 4 rodata []`
   (ret at `sAt 0`).  A W-mode version of the entry/loop/exit segments is needed, or a
   stack-shift homomorphism from the entryS proofs.
4. **Dead-register/flag state at the tail.** At the x4 tail state rdx/rsi/rdi are advanced
   pointers/count; rax/rcx/r8–r11 and flags differ from `entryW` and are dead for x1 (x1's
   first flag read is the `cmp` at pc 13, after the prologue).  `AvxX1All.correctW` is stated
   exactly at `entryS 24`, and `AvxX1W.correctW` exactly at `entryW`; composing at the tail
   needs either a contract parameterized by those dead values or a dead-register invariance
   lemma (the existing `gprRel`/`mapState_inst` only replaces number lanes by location
   variables, not arbitrary pointer leftovers).
5. **x8's stack shift is not a simple tail jump shape.** x8 does `push rbp; mov rbp,rsp;
   and rsp,-32; sub rsp,928`, saves r12–r15, and on exit restores them, `mov rsp,rbp;
   pop rbp; jmpTail x4`.  A chain model has to account for the 8-byte push and the 32-byte
   alignment between the x16 and x8 frames; x16 itself has no stack frame.  The wrapper's own
   `and rsp,-32` is already modelled concretely (`align_hom`/`alignStep`).

The next increment is the W-mode multi-lane segment generator (`X86LoopVW`) producing, for each
of x4/x8/x16, the `entryW` prologue to the loop head, one `W`-block iteration head→head under
`(in + 64W, out + 32W, count − W)`, and the exit head→tail segment; then the chain composition
with the scalar kernel (x4→x1, x8→x4→x1, x16→x8→…) at distinct rodata regions, and the
`Fits .avx2`/`Fits .avx512` facts.  The x4 loop-head segmentation above is the body half of
that generator's output and is reusable as soon as the entryW↔entryS bridge exists.

### Framed iteration (done: `AvxX4LoopFrame.lean`)

`Hashtree/Proofs/AvxX4LoopFrame.lean` supplies the framing layer the loop turn was missing:

* `KH'_log` / `KH'_logB`: every write of one turn is an output cell, or a stack cell at a
  constant offset below the entry offset 24 (checked in the kernel over the generated cut);
* `outLog_map_KH'`: one turn's log, mapped through `mapAddr σ` / `mapCell e σ`, satisfies
  `OutLog` for any `σ, e`, so the next turn can be framed under it;
* `iter_step`: one turn behind an accumulated `OutLog M` replays via `run_fr`, with the
  symbolic environment restarted as `ecomb e σ (view M mem0c)` and `mapState_nOnly` moving
  the concrete state onto it; the result is the invariant head under `sigmaOf tau σ` with
  log `turnWrites ++ M`, again `OutLog`;
* `loop`: for any `j, s` with `4 ≤ s < 8`, `j` turns from `fr M (mapState e σ KHL2)` reach
  `fr M' (mapState e' (sIt j σ) KHL2)` with `OutLog M'` whenever `σ 2 = 4j + s`.  The count
  drops by four per turn and the residual count stays in `[4,8)` for the final batch.

One correction to the earlier plan: a full turn's 23-instruction tail already contains the
eight output vstores, so a count divisible by four leaves nothing for the scalar tail to
store; x1 is then called with count 0 and returns without writing.  The final batch is
therefore head + body + the pilot's 27-step exit slice `K200 → K201`; it needs `A0`
(`4 ≤ c`) in the head/body and `A1` (`4 ≤ c < 8`, `c ≠ 0`) in the exit slice.  This is why
`loop` stops at residual count in `[4,8)` instead of iterating down to zero.

### Blocker — `KSpec` cannot be satisfied by the multi-lane kernels (found 2026-11-13)

`Fits .avx2` and `Fits .avx512` — the two hypotheses of `wrapper_correct` — cannot be
discharged against the current `KSpec`, and the README plan for them is inconsistent with
the generated models.  Two separate issues.

**1. Every multi-lane kernel ends in a tail call, while `KSpec` requires `fin.tail = none`.**
(`Hashtree/Proofs/WrapperAmd64.lean:45-51`, the requirement on line 50; `wrapper_kernel`'s
own statement asks for the same on line 262.)  Machine-checked evidence from the committed
generated files:

- `Hashtree/Gen/AvxX4P/P200.lean:19`: `K201` is
  `{ pc := 4143, halted := true, tail := some "hashtree_sha256_avx_x1", err := none }`,
  the x4 run's final state (`Final.run_final`, `out_final`, and `AvxX4Exit.exit_batch`).
- `Hashtree/Gen/Avx2X8P/D210.lean:18`: `K211` is
  `{ pc := 6080, halted := true, tail := some "hashtree_sha256_avx_x4", err := none }`,
  the x8 run's final state at c = 8 (`Final.run_final`).
- `Hashtree/Kernels/X86/Avx512X16.lean:18`: `.jccTail .b "hashtree_sha256_avx2_x8"`;
  `.jccTail` sets `halted := true` and `tail := some name` when taken
  (`Hashtree/Asm/X86.lean:526-531`).
- The unconditional exits are `.jmpTail`s: `Hashtree/Kernels/X86/AvxX4.lean:4153` and
  `Hashtree/Kernels/X86/Avx2X8.lean:6090`.

The contract is load-bearing because the wrapper model discards a tail: `callK`
(`Hashtree/Proofs/WrapperPre.lean:23-25`) runs the kernel and then returns
`{ r with pc := 0, halted := false }`, i.e. it always pretends the kernel returned to the
caller's `post` code.  With a tailing kernel this would continue at `post` without the
tailed kernel ever running, so `wrapper_kernel` would be unsound; requiring `tail = none` is
what rules that out.  A chain-aware `callK` can follow the tail exactly like `runChain`
does; note that tail calls share the single return marker pushed by `pushRet` (x8 restores
its frame before `jmpTail`; x4 adds 408 before `jmpTail`), so the final `x1` `ret` returns
to the original caller.

The control flow gives a tail for every positive count: x4 returns only at c = 0 (pc 3);
0 < c < 4 goes to 4142 → 4143 (KSm, tail x1, `AvxX4Entry.small_prefix`) and c ≥ 4 loops and
exits the same way (K201, tail x1).  x8 adds its frame and at pc 12 tests c < 8; both that
branch and the loop's exit reach the epilogue 6074-6079 and then the `jmpTail` at 6080.
x16 tests c < 16 at pc 7-8 and takes `.jccTail` to x8 directly or after its batches.  On
these paths the only halting instruction is a tail jump, so for c = 8 (x8) the run either
has not halted yet (too few steps) or ends at K211; it cannot end with
`halted = true ∧ tail = none`, and `Fits .avx2` is false as stated.  For x16 the
same holds at every c ≥ 1: after its batches the residual is < 16, and pc 8 is reached
with that residual (the `jb` is taken for residual 0 too).  A concrete tail witness already
exists for the x4 program at c = 1: `AvxX4Entry.small_prefix` reaches KSm in exactly 8 steps
from `entryW` for any `WfMemW`/`EnvMem`, and `KSm_tail = some "hashtree_sha256_avx_x1"`.

**2. Even with a chain contract, the rodata model is per-kernel, so one region-4 memory
cannot satisfy two kernels' `WfMemW`.**  `WfMemW` places the kernel's list at region 4
(`Hashtree/Asm/X86SymW.lean:127`), `run` resolves a `ro := some n` operand in the region it
is given (`Hashtree/Asm/X86.lean:543`), and `KSpec` passes region 4.  At the offsets a
tail-called kernel reads, the caller's table holds different values (measured on the
committed lists):

- x8 reads 0, 4096, 4352; in x16's table the blocks at 4096/4352 are not x8's (x8's 4352
  block sits at 4096 there, and x16 itself reads 4096 at `Avx512X16.lean:61`).
- x4 reads 0, 2048, 2176; in x8's table x4's 2048 block is at 4112 and its 2176 block at 4352.
- x1 reads 0, 256, 544, 560, 576; none of those 32-byte blocks occurs anywhere in x4's
  2192-byte table.

The validation harness already models the correct semantics: in `Hashtree/Asm/X86Run.lean`
every `Prog` has its own `ro : Region`, `mem0` puts each program's rodata in that region, and
`runChain` follows the tails.  A chain contract should be built the same way (a region
parameter for the rodata, one memory holding all kernels' tables in distinct regions), not
by trying to place all tables in region 4.

**Proposed contract change** (needs sign-off: it changes `KSpec`, `wrapper_kernel` and the
meaning of `Fits`).  Give the spec a region parameter and a continuation for the tail case:

    def KSpecC (kprog : Array Instr) (ro : Region) (rodata : List Nat)
        (steps : Nat → Nat) (D : Nat) (Next : Nat → State E Lin → Prop) : Prop :=
      ∀ c ..., WfMemR ro rodata ... → ... →
        let fin := run kprog ro mem0c orcC (steps c) (mapState env0 σ entryW)
        fin.halted = true ∧ fin.err = none ∧ Foot ... ∧ OutOk ... ∧ RegsOk ... ∧
          (fin.tail = none ∨ ∃ name, fin.tail = some name ∧ Next c fin)

and have `wrapper_kernel` follow the tail chain the way `runChain` does, with one `KSpecC` per
kernel; `Next` carries the callee ABI (x8's `and rsp,-32`/`sub rsp,928` at pcs 6-7, the
no-frame x16 case, callee-saved registers and the stack/rodata handoff).  The alternative is
to generate one code image with rebased pcs so that `run` continues through the `jmpTail`;
that is a generator change, not a proof change.

Until one of these lands, `wrapper_correct` stays conditional and the manifest statuses stay
`proved-fixed-count` for avx_x4/avx2_x8/avx512_x16.  No `sorry` was introduced: the fixed-count
theorems and the x4 loop/exit work are complete proofs of their stated claims.

### Chain-aware contract (`Hashtree.Proofs.X86Chain`)

`Hashtree/Proofs/X86Chain.lean` (new module, 2026-11-13) is the reusable tail-call chain
contract.  It contains:

- `Link` (tail-call name, program, rodata region, steps) and `Spec` (link + pre/post);
- `resume` (the state handed to the next kernel: pc 0, halted/tail cleared) and `chainRun`
  (runs the links in order on one shared memory, following `tail = some <next name>`);
- `KSpecC` — the per-link obligation: from `pre`, a link either returns (`tail = none`,
  `post`) or tails into the next link's `pre`;
- `chain_sound` (proved): `KSpecC` implies the chain ends with `err = none`, `tail = none`
  and the last link's `post`;
- `callChain` — the tail-following replacement for `callK` (which discarded the tail), and
  `chainRun_fr` (proved): a chain commutes with a memory-log frame, the lemma the wrapper
  needs because its call state is `fr L` of the kernel entry.

Before/after obligations:

- Old `KSpec`: one `run` of one program, one rodata list in region 4, requires
  `fin.tail = none`; it holds only for the terminal kernels (`shani`, `avx1`) and fails for
  x4/x8/x16, so `Fits .avx2`/`Fits .avx512` were vacuous for the shipping dispatch.
- New `KSpecC`: every link has its own `pre`/`post` and its own rodata region; a tail is
  permitted and hands the next link the `resume`d state; `chain_sound` composes the links.

Exact remaining obligations:

1. Per-link pre/post (the entry bridges).  For each adjacent pair, the caller's post-state

Semantics facts read from `Hashtree/Asm/X86.lean` / `Core.lean` while doing the cases:

- The only region tests in `exec` are `r = rNum` (`alu .add`, `sub`, `shl`, `cmp`, `test`)
  and the `ret` pattern `.ptr { region := 5, _ }`.  Everything else is region-covariant:
  `baseAddr` with `ro := some n` builds `⟨ro, addr⟩` from the immediate, `effAddr` = base +
  register offsets, and `gCtl`/`gData32` return register contents.
- `mov w` writes through `setData32` (a `.dat 32` cell) when `w != 64`, otherwise `setG`;
  `movst` branches on `s.getG src` being `.num`/`.ptr` and stores accordingly.
- `alu` first branches on `w = 64`, then on `op = .xor /\ src = .reg d`; `.and` uses
  `andInt` on `Ctl.asInt` of both operands; `.add`/`.sub`/`.shl`/`cmp`/`test` require the
  two region classifications (`x.region = rNum \/ y.region = rNum`, `x.region = y.region`),
  which is why commutation needs `f_eq_rNum`/`f_inj`.
- `push`/`pop`/`ret` match `s.getG rsp`; `ret` matches `loadVal mem0 s sp` against a
  pointer in the literal region `5` and sets `halted := true` (no `next`).
- `jcc`/`jccTail` branch on `s.flags`; `jccTail` compares the branch state pc with the
  literal `1000000000` and, if taken, sets `halted := true, tail := some name`.

Lean gotchas (recorded so the next module does not rediscover them):

- `by_cases hw : w = 64` followed by a `·` bullet inside a `<;>` chain makes Lean parse the
  bullet as an *argument* (`hw : w = sorry`); put the `by_cases` on its own line.
- Eliminate the do-binds before touching conditions: `simp only [map_eq_bind, emap_bind,
  bind_ok_e, bind_error_e, emap_pure, emap_throw, emap_ok, emap_error, emap_dite]`.
- `rw [if_pos h]` rewrites only the syntactic occurrence, not the one under `emap`;
  `simp only [if_pos h]` rewrites both.  Bare `if_pos`/`if_neg` (no proof term) in a
  `simp only` list do nothing.
- Do not pass `map_eq_bind` to a full `simp`: it loops with the default `bind_pure_comp`
  (`maximum recursion depth`); use `simp only`.
- Do not `simp only [RegionRenaming.addr]` while `loadVal_ren`/`storeVal_ren` still have to
  fire: it expands `rho.addr a` and the lemmas stop matching.
- `cases hA : f x` only rewrites the scrutinee it was given.  When the goal holds a defeq but
  syntactically different term, supply the `rfl` bridges explicitly: `addr_off`
  (`(rho.addr a).off = a.off`), `addr_region`, or a local `have h : ... := rfl`.
- Rewriting `(rho.state s).halted` to `s.halted` (`state_halted`) *inside* an `if` is a
  dependent rewrite: the elaborated `Decidable` instance keeps the old condition and the term
  stops typechecking ("motive is not type correct").  Split the `if` with `split` and prove
  the two cases from the split hypothesis (`run_ren`).
- Structure-literal matches (`| .ptr { region := 5, off := off }`) are not reduced by `simp`.
  Either rewrite the discriminants to a canonical literal (`ret`), or `split` on the match and
  recover the region equality from the guard by `injection`.
- `f_eq_rRet`/`f_eq_rNum` take `rho` explicitly: `f_eq_rRet rho h5 r`.

                                                              -- .pb return marker at σ 9..σ 9+8
    EnvMem env0 σ mem0c
    σ 2 = (c : Int)
    ∀ o, mem0c ⟨rIn, σ 0 + o⟩ = .dat ((inp o).zeroExtend 32) 0

`push = []` is right for a tail call: the caller's return marker is already in place and
nothing else is pushed.  A proof carried out at the *explicit* entry state `entryWx`
(`AvxX4WPrep`) converts with `mapState (envM e mem0c σ) (upd15 σ) entryWx = mapState e σ entryW`;
`upd15 σ` only redirects the dead `rax` symbol `15` to `σ 1`, and `envM` reads the memory keys
from `mem0c` at `σ`.

**Post-condition, `0 < c < 4` (done, `AvxX4ToX1.x4_small_to_x1`).**  Eight instructions
(`jne` after `cmp rdx,0`, `cmp rdx,4`, `jl`), then a tail call: the cut `KSm` has
`gpr = entryW.gpr`, `vr = entryW.vr`, `mem = []`, `rsp` restored to `sAt 0`,
`tail = some "hashtree_sha256_avx_x1"`, `err = none`, `assume` = the two conditions
`0 ≠ c`, `c < 4` (`KSm_assumeOk`).  This already composes with x1's all-count contract.

**Post-condition, `c = 0` (done, `AvxX4Entry.zero_run`).**  Four instructions, returns:
`halted = true`, `tail = none`, `err = none`, `rsp = sAt 8` (`σ 9 + 8`, the return marker
popped), no writes, callee-saved registers restored, `Foot`/`OutOk`/`RegsOk` as in
`AvxX4Entry`.

**Post-condition, `c >= 4` (done: state trajectory; `AvxX4LoopWEntry`, `AvxX4LoopWAll`).**
Write `c = 4 * (j + 1) + s` with `4 <= s < 8` and start from
`fr M (mapState env0 σ entryW)` with `OutLogW σ M`, `WfMemW rodata [] env0 σ mem0c` and
`σ 2 = c`.  Two theorems reach the W-mode exit cut `K201W`:

* `x4_runW_last` (`4 <= c < 8`, `σ 2 = c`): `72 + (6062 + 27) = 6161` steps — the 72-step
  W-mode entry slice (`entry_runW`: 4 branch instructions plus the 68-step head slice), the
  body (`body_runW`, 199 slots, 6062 steps), and the 27-step exit slice;
* `x4_runW` (`c = 4 * (j + 1) + s`): `((72 + (6062 + 23)) + j * TURNLEN) + (68 + (6062 + 27))
  = (6157 + j * 6153) + 6157` steps — entry to the first body cut (`entry_runW`), first body
  plus the 23-step tail (`body_runW` + `slice_sound`, extending the log `M` by the turn's
  writes), `loopW`'s `j` framed turns (`TURNLEN = 6153` each), then `final_runW` (head slice,
  body, exit slice).

Both end at `fr M' (mapState e' (sIt (j + 1) (upd15 σ)) K201W)` with
`OutLogW (sIt (j + 1) (upd15 σ)) (K201W.mem.map ... ++ M')` (`K201W_logB`), and at the cut

    K201W.tail = some "hashtree_sha256_avx_x1"
    K201W.err = none
    K201W.getG 4 = .ptr ⟨rStack, sAt 0⟩    -- the x4 frame is popped, rsp back at the marker

so `rdx`/`rcx` carry `c mod 4 = s - 4` into x1, and `rsi`/`rdi` have advanced by 256/128 per
turn (carried by `sIt`, not by the register lins).  The runs are carried out at `upd15 σ`
(symbol 15 is the dead `rax` of `entryWx`; `upd15` is the identity on 9 and on every register
symbol), and `WfMemW`/`OutLogW` survive it because `WfMemW`'s only stack read is at `σ 9`
(`upd15_9`, `tau_s9`, `sIt_s9`, `wfMemW_s9`, `outLogW_s9`); a log is harmless when its stack
writes stay below the return marker (`OutLogW`, `wfW_view`).

A caller above x4 must produce exactly the pre-condition above at *its* tail call, with x4's
table at region 4 and its own at a fresh region (x8 uses 4096 in the shipped image).

What is **not** covered yet in W mode is the *output-byte* part of the exit (`out_finalS` /
`exit_batch` in the absolute-stack version): it needs an `InvC` chain over the W cuts (the W
slices are checked with empty tree lists), and the hand-off of `K201W` to the x1 entry
state (`mapState env' σ' entryW` up to flags) that `AvxX1W.correctWAt` expects.  That hand-off
is *not* a reshaping of the cut: three caller-saved registers (`rax`, `rcx`, `r9`) carry
different values and no single `σ'` matches `entryW`; see the blocker section.  Until those
exist, the W-mode x4 link proves the *state* trajectory, the accumulated log and the tail,
not the output bytes.

### Blocker: the x4 W-mode exit cut is not the x1 entry state (found 2026-11-13)

Composing the x4 W-mode link with x1 is not the "reshaping up to flags" the earlier plan
assumed.  Evaluating `K201W` (the exit cut, `AvxX4LoopWEntry`) at `σ' = sIt (j+1) (upd15 σ)`
and comparing with `entryW` at `σ₁ = sigmaOf tau σ'` (one further loop substitution: the
41-step final segment has already advanced `rsi`/`rdi` and decremented the count by four in
its register expressions) gives, register by register:

* `rdx` (`-4 + σ' 2`), `rsi` (`256 + σ' 0`), `rdi` (`128 + σ' 1`), and every callee-saved
  register (`rbx`/`rbp`/`r12`/`r13`/`r14`/`r15`, restored from the frame) and `rsp`
  (`sAt 0`) are *exactly* `entryW`'s register values at `σ₁`;
* `vr` is `entryW`'s `vId` lanes (all 32 registers);
* `mem` is fine: the cut's own 1280-entry write log is exactly what the x4 post already
  folds into the caller's log `M'`, so the x1 link can take `fr M' (mapState e' σ₁ entryW)`;
* `flags` differ (the x1 spec already allows any flags, `correctWAt_entry`).

But three registers differ, and they are caller-saved scratch:

    rax  (0): entryW `ptr ⟨rOut, sym 1⟩`   vs K201W `ptr ⟨rOut, sym 15⟩`  (upd15's dead rax)
    rcx  (1): entryW `ptr ⟨rNum, sym 2⟩`   vs K201W `ptr ⟨4, 1024⟩`        (x4 rodata constant)
    r9   (9): entryW `num (n 18) (n 19)`   vs K201W `ptr ⟨rNum, 1024⟩`

No single `σ₁` makes those match (`σ₁` is already fixed by `rdx`/`rsi`/`rdi`), so
`resume (mapState e' σ' K201W)` is *not* `{mapState e' σ₁ entryW with flags := fl}`, and the
x1 contract (`AvxX1W.correctWAt_entry`) cannot be applied directly.  This blocks the c >= 4
x4->x1 handoff, and by the same argument every multi-lane tail (x16->x8, x8->x4) that leaves
junk in caller-saved registers at its tail call; the previously published pre-condition (the
caller must hand x4 exactly `entryW`) is therefore not satisfied by a real tail call either.

Resolution: the x1 link needs an entry contract that tolerates arbitrary values in the
caller-saved scratch registers it overwrites before reading.  The x1 program (generated from
the shipped object, `Kernels/X86/AvxX1.lean`) does write them first: `lea rcx, [rip+0x100]`
at pc 15 precedes the first `rcx` read (pc 16), the first `rax` read is after `mov eax,[rcx]`
at pc 16, and the first `r9` read after `mov r9d,[rcx+0x10]` at pc 20.  So the proof route is
a generic dead-register lemma over the instruction model: the relation "agree on every field,
and on every register except a set `S`" is preserved by any instruction that never reads `S`,
so a `decide +kernel` scan of the instruction list against a computable read-set function
gives `run`-insensitivity, and the x1 post-condition (which mentions no caller-saved
register) transfers.  This is new `Asm` machinery (read/write sets per instruction and a
`run` congruence), not a reshaping of the x4 cut.  Until it exists, the x4 W link stops at
the cut, as stated in the interface section.

### Scoping: dead-register congruence for the x1 hand-off (design only, 2026-11-13)

Goal: replace the exact entry contract `mapState e' σ₁ entryW` by "agrees with `entryW` on the
registers x1 does not read before writing", so the x4 W exit cut `K201W` (and, later, the
x8/x16 tail cuts) can be handed to x1.  The x1 post-condition is insensitive to this: its
`AvxX1WAt.correctWAt` mentions only `halted`, `err`, `tail`, `mem` (`InRange`/`OutOk`) and
`RegsOk env0 σ` (GPRs 3, 4, 5, 12, 13, 14, 15), so the post transfers to any entry state that
agrees with `entryW` outside `{rax, rcx, r9}`.

Scoping prototype (compiled on VM1, not part of the repo): `/root/r2w/DeadRegsProbe.lean`,
`/root/r2w/DeadRegsScan.lean`.

#### Definition

    def flg : Nat := 16                       -- pseudo-index for the flags; real GPRs are < 16

    structure AgreeOn (S : List Nat) (s1 s2 : State α γ) : Prop where
      pc halted tail err mem vr assume : ... = ...     -- all equal
      flags : flg ∉ S → s1.flags = s2.flags
      glen  : s1.gpr.length = s2.gpr.length
      gpr   : ∀ i, i ∉ S → s1.getG i = s2.getG i

`S` is "may still differ": it shrinks when an instruction writes a register, and the analysis
joins with the union (a larger `S` is weaker).  `eraseReg S d` removes a written register.
Proven in the prototype: `mem_eraseReg`, `AgreeOn.mono` (`S ⊆ T`), the list lemmas
`getD_set_self`/`getD_set_ne` (so `getG` after `setG`), `getG_setG_self`/`getG_setG_ne`,
`AgreeOn.next`, `AgreeOn.setG` (same value written to a register outside `S`), and
`AgreeOn.setG_diff` (written register leaves `S`; written values equal).

Representative exec-preservation case, proved end to end (`exec_mov_reg64`):

    AgreeOn S s1 s2 → r ∉ S → d ≠ flg → ¬ halted s1 → ¬ halted s2 →
      AgreeOn (eraseReg S d) (exec ro mem0 orc (.mov 64 d (.reg r)) s1)
                             (exec ro mem0 orc (.mov 64 d (.reg r)) s2)

It exercises the whole shape: halted agreement, the fetch step, value equality from `gpr`,
the `setG`/`next` bookkeeping, and the flags side condition.

#### Read sets and the check

- `readsOf`/`writesOf : Instr → List Nat`, structural over all 39 constructors.  `readsOf`
  collects the GPRs reached through `MemRef.base`/`index`, `GSrc`, `VSrc`, and adds `flg` for
  `cmp`/`test`/`jcc`/`jccTail`; `xor d,d` reads nothing (zeroing idiom); `push` reads `rsp`
  and its source; `pop`/`ret` read `rsp`.  `writesOf` lists every written GPR and adds `flg`
  for the flag-setting instructions.  Memory writes are deliberately *not* cleared from `S`:
  `AgreeOn` keeps the memory log equal, and equal address/value writes append equal entries.
- `transfer D i := D.filter (¬ written by i)`; `successors` (`jmp` → target;
  `jcc` → target, pc+1; `jmpTail`/`ret` → none; `jccTail` → pc+1; else pc+1); forward union
  fixpoint from the caller-side set `S0`.
- `checkAt prog Ds pc` = (instruction reads avoid `Ds pc`) ∧ (every successor contains
  `transfer (Ds pc) i`); `check` = all pcs.
- Concrete x1 result with `S0 = {0,1,9,16}`: `Dsx` is `{0,1,9,16}` on pcs 0–7, `{0,1,9}` on
  8–15, `{0,9}` at 16, `{9}` on 17–20, `∅` on 21–4056, `{0,1,9}` on 4057–4064.  29 non-empty
  program points; after the prologue nothing is live except the zero-count epilogue.
  `check` evaluates to true.
- Kernel checking: one `decide +kernel` of `check` over all 4065 pcs *times out* (kernel
  deterministic timeout after 5m19s).  Factored scheme, ~3 s: the 21-instruction prologue and
  the 8-instruction zero-count epilogue are concrete `decide +kernel` facts; the body 21–4056
  is discharged symbolically (`Dsx pc = []` from the interval, then
  `unfold checkAt; split; simp [transfer]`); the 4056→13 loop-back containment is a concrete
  `decide +kernel` fact.  The fixpoint table itself is computed by `#eval!`, but the final
  proof re-checks the table at every program point, so the computation is not trusted.

### Dead-register congruence: checkpoint (3) done (2026-11-13)

Checkpoint (3), `run_agree`, is in the same module (`formal/lean/Hashtree/Asm/X86Agree.lean`,
now 1620 lines, 90 declarations, no `sorry`).  Nothing else in the library changed.

Design decision (option (a), success-driven induction; no disjunctive step relation): the only
consumer of the run congruence is the x1 link, whose post `correctWAt` already carries
`fin.err = none`; a free hypothesis is cheaper than a disjunction threaded through the run
lemma and `Dsx`.  The induction stays total because `AgreeR` excludes mixed outcomes: at a step
whose reference result is `ok`, the peer result is `ok` and yields `AgreeOn (eraseAll S ws)`;
and a shared failure at that step would leave the reference run's final `err` non-`none`,
contradicting the hypothesis.

- `run_agree` (the statement): for a `Ds : Nat → List Nat` justified at every pc by
  `hsound : prog[pc]? = some i → (∀ r ∈ readsOf i, r ∉ Ds pc) ∧
  (∀ d ∈ gprWritesOf i, d ≠ flg) ∧
  (∀ p' ∈ successors pc i, eraseAll (Ds pc) (writesOf i) ⊆ Ds p')`, and for a reference run
  that does not fail, `AgreeOn (Ds s1.pc) s1 s2 → (run … n s1).err = none →
  AgreeOn (Ds (run … n s1).pc) (run … n s1) (run … n s2)`.  No hypothesis on `s1.err` and no
  error hypothesis on the peer run; `AgreeOn.err` gives the peer run's success.
- `successors pc i` (`jmp` → `[t]`, `jcc` → `[t, pc+1]`, `ret`/`jmpTail` → `[]`, else
  `[pc+1]`) and `execE_ok_pc`: every successful body ends at `pc` again (`ret`, tail calls,
  the `jccTail` tail-call arm) or at one of those successors.  The body is proved once with a
  39-constructor case over `OkProp P r := ∀ s', r = .ok s' → P s'`: `OkProp_bind` peels the
  do-blocks' binds, `OkProp_ite` splits the `if`s, and the pc of the final state follows from
  pc-projection lemmas (`setG_pc` … `storeVal_pc`, `branch_pc_cases`), all `rfl`-level except
  `storeLanes_pc` (induction), `storeVal_pc` (cases on the value) and `branch_pc_cases`
  (cases on `c.decideC` and the oracle direction).
- Step soundness comes from `execE_agree` at each step; the invariant is moved from
  `eraseAll (Ds pc) (writesOf i)` to `Ds s1'.pc` with `mem_eraseAll` (pc unchanged) or
  `hsound` at the landed successor, and `AgreeOn.mono`.
- The failing-step case needs no `exec_keeps`: if `execE` errors, `exec` is `s1.fail e`, which
  is halted, so the rest of the run is that state (`run_of_halted`), whose `err` is non-`none`
  (`fail_err_ne_none`) — contradicting the hypothesis.  A fetch outside the program is
  closed the same way.  Hence `run_agree` is self-contained in this module (it does not
  import `X86RunHom`, and its helper `run_of_halted` avoids that module's `run_halted` name).

### Dead-register congruence: checkpoint (4) done (2026-11-13)

Checkpoint (4), the x1 hand-off, is a new module
`formal/lean/Hashtree/Proofs/AvxX1Agree.lean` (namespace `Hashtree.Proofs.AvxX1Agree`,
self-contained: imports only `Hashtree.Proofs.AvxX1Entry` and `Hashtree.Asm.X86Agree`, so no
`X86RunHom` import and no `run_halted` name clash).  Nothing else in the library changed apart
from one rename needed for the import to coexist: `Hashtree.Asm.X86Agree.bind_ok` became
`bind_ok_agree` (the name `Hashtree.Asm.X86.bind_ok` already exists in `X86Exec`, which is in
`AvxX1Entry`'s import closure; it was the only clashing declaration).  No `sorry`.

The table.  `Dsx : Nat -> List Nat` is the concrete dead-register analysis from the entry set
`{rax, rcx, r9, flags}`:

    pc 0-7      [0, 1, 9, 16]
    pc 8-15     [0, 1, 9]
    pc 16       [0, 9]
    pc 17-20    [9]
    pc 21-4056  []                (the whole loop body)
    pc 4057-4064 [0, 1, 9]        (the zero-count epilogue)

29 non-empty program points.  Exposed ends: `Dsx_entry : Dsx 0 = [0, 1, 9, 16]` and
`Dsx_exit : Dsx 4064 = [0, 1, 9]` (the value the chain step rewrites its exit agreement with).
`Dsx_body : 21 <= pc -> pc <= 4056 -> Dsx pc = []` is the shape fact for the body.

Soundness is factored, not a whole-program `decide`:

- `checkAt pc` is the local condition at one program point: every read avoids `Dsx pc`, and
  every successor of `pc` keeps every register in `eraseAll (Dsx pc) (writesOf i)`.
- prologue: `checkAt_lt_21 : (List.range 21).all checkAt = true`, `decide +kernel`;
- epilogue: `checkAt_epilogue : (List.range 8).all (fun k => checkAt (4057 + k)) = true`,
  `decide +kernel` (includes the concrete `ret`);
- body: `checkAt_body`, symbolic — `Dsx pc = []` makes both local conditions vacuous, and the
  loop-back edge `4056 -> 13` carries nothing (`Dsx 4056 = []`, so the transfer set is
  empty, and `Dsx 13 = []` as well);
- `prog_size : prog.size = 4065` and `checkAt_all : forall pc, pc < prog.size -> checkAt pc`
  tie the three ranges together, so a pc left out of every range fails the build;
- the flag side condition is separate, because it depends only on the instruction's written
  registers, not on the pc: `flagOkAll : prog.toList.all (fun i => (gprWritesOf i).all
  (fun d => decide (d != flg))) = true`, one `decide +kernel` pass over `prog.toList`
  (0.4 s).  The per-pc array-indexed form (`List.range prog.size` with `prog[pc]?`) ran
  > 4m20s at 71 GB RSS and had to be killed; the linear `toList` pass replaces it.  A negative
  control (`d < 10`) fails quickly, so the kernel really evaluates the scan.
- `hsound` combines `checkAt_all` with `Array.getElem?_eq_getElem`,
  `Array.getElem_mem_toList`, `List.all_eq_true` and `of_decide_eq_true`.  The table is never
  trusted: every program point is re-checked here, and the read/write sets themselves are
  bounded semantically by `execE_agree`, so a register missing from `readsOf` would make that
  kernel-checked theorem false.

The bridge.  `AgreeOn.symm` is local (the module does not import `X86RunHom`), together with
`gpr_get_of_getG`, `gpr_of_agree`, `regsOk_agree` and `not_mem_Dsx` (no `Dsx` value contains
`rax/rbx/rcx/rdx/rsi/rdi/r8-r15`; the 7 `RegsOk` registers are all outside).  `correctWAt_agree`
takes `hs : AgreeOn [0, 1, 9] s {mapState env0 sigma entryW with flags := fl}`, builds
`hpre : AgreeOn (Dsx 0) entry s` from `AgreeOn.symm hs` + `mono` (`[0,1,9]` is a subset of
`[0,1,9,16]`) + `Dsx_entry`, applies
`run_agree prog r mem0c orcC Dsx hsound (steps c) entry s hpre herr` with `herr` from
`correctWAt_entry`, and transfers the postcondition: `halted`/`err`/`tail` by symmetry,
`mem`/`InRange`/`OutOk` through the `mem` equality, `RegsOk` through `regsOk_agree`.  The caller
instantiates `fl` with the cut state's flags (the relation asks for flag equality because
`flg = 16` is not in `[0,1,9]`), so there is no extra flag hypothesis.
