# R4: linux/riscv64 machine-code proofs

Status log: `results/r4-riscv-log.md` on the control machine.  Branch `research/formal-r4-riscv`
based on `research/formal-verification` (0a724af).  Lean 4.35.0, all builds on VM2.

## Contract (what the three kernels are proved to do)

The three RV64 kernels (`hashtree_sha256_riscv_x1`, `..._zbb_x1`, `..._crypto`) implement

    void hashtree_hash(const void *out, const void *in, size_t count)

in the LP64D calling convention: `a0 = out`, `a1 = in`, `a2 = count`, `ra` = return address,
`sp` = stack.  `count` is the number of 64-byte input blocks.  For every `count` the kernel
writes `32*count` output bytes; output byte `32*n + j` is byte `j` of
`SHA-256(pad(block n))`, where `pad` is the fixed padding block (the kernel hashes every 64-byte
block independently, starting from the same `.LDIGEST` constants, with the precomputed padding
words at `.LPADDING`; this is exactly `Hashtree.Spec.blk inp n`).

Formally (one theorem per kernel, `Hashtree/Proofs/Rv{X1,ZbbX1,Crypto}All.lean`):

    theorem correct (c : Nat) (inp : Nat → Byte) (env0 : Key → W32) (σ : Nat → Int)
        (mem0c : Addr Int → Cell W32 Int) (orcC : Nat → Bool)
        (hw : WfMemR 10 11 rodata gotT mem0c) (he : X86Sym.EnvMem env0 σ mem0c)
        (hc : σ 2 = c) (hσ0 : 0 ≤ σ 2) (hb : 32 * σ 2 < 2 ^ 63)
        (hin : ∀ o : Nat, mem0c ⟨rIn, σ 0 + o⟩ = .dat ((inp o).zeroExtend 32) 0) :
        let fin := Riscv.run prog pe mem0c orcC (steps c) (mapState env0 σ (entryS 0))
        fin.halted = true ∧ fin.err = none ∧ fin.tail = none ∧
          InRange (σ 1) (32 * c) fin.mem ∧ OutOk inp (σ 1) c fin.mem ∧
          ∀ r ∈ [2], fin.getG r = (mapState env0 σ (entryS 0)).getG r

with `steps c = H + c * IT + EX` (13 + 6300*c, 13 + 4140*c, 11 + 2732*c).  `InRange` says every
logged write is either one of the `32*c` output bytes or a byte of the kernel's own frame;
`OutOk` says output byte `32*n + 4*i + b` is byte `4*i + b` of `blk inp n`.  The entry state
`entryS 0` sets `ra` to the return region, `sp` to the symbolic stack pointer, and every other
register to a location variable; `count` is the symbolic integer `σ 2`.  The last clause is the
*dynamic* `sp` preservation (`PRES = [2]`, `ENTRY = entryS 0`): after the run `sp` equals the
callee-entry `sp` (`.ptr ⟨rStack, 0⟩`), derived from the exit's restore through the loop
induction, not from a static argument.

What the theorem does **not** yet state (see "Remaining gaps"): the saved callee registers `s9`
and `s10` are not exposed by `correct` — the documented `PRES = [2, 25, 26]` instantiation
fails to typecheck (see the saved-registers section for the exact failure); the ten registers the
kernels never write are covered by a separate theorem, `correct_regs_*`.  The Go
wrapper (`$0-24` frame, B7 and the call/return stream) has its own model and proofs in
`Hashtree/Kernels/Riscv/WrapperLinux.lean` + `Hashtree/Proofs/RvWrapperLinux.lean`, and the
dispatcher's `init_and_hash`/`hashtree_init` are proved for the finite classes of the probe's
tested bits (`Hashtree/Proofs/RvDispatchInit.lean`); a *symbolic* `hwprobe`-driven selection is
not expressible in the model (see below).

Steps (model instruction count), measured from the generated programs (2026-11-12):

| kernel | len | loop head `H` | head | iteration | exit | `steps(c)` |
|---|---|---|---|---|---|---|
| `x1` | 6312 | 7 | 7 | 6300 | 6 | `13 + 6300*c` |
| `zbb_x1` | 4152 | 7 | 7 | 4140 | 6 | `13 + 4140*c` |
| `crypto` | 2742 | 6 | 6 | 2732 | 5 | `11 + 2732*c` |

Segment meanings: **head** = prologue `pc0..H` (ends at the loop head); **iteration** =
`H` (branch to the body taken) plus the body `H+2..L` ending with `jal 0,H` back to `H`, i.e.
`L - H` steps returning to `H` (`x1`: `7 -> 9..6307 -> 7`, `6307 - 7 = 6300`); **exit** = `H`
(branch not taken when `a0 = a2`) plus `H+1` (`jal 0,epilogue`) and the epilogue.
Bodies end with `addi a0,a0,32; jal 0,H`; all three kernels have identical data bodies
except the byte-swap of the two output words holding the length/counter (`slliw`/`lui`/`and`/`or`
for x1, `rev8`/`srai` for zbb_x1 and crypto).

Prologue/epilogue save slots: `x1` and `zbb_x1` save `s9,s10` (`sd 26,64(sp); sd 25,72(sp)`) and
restore them in the exit; `crypto` saves only `s9` (`sd 26,64(sp)`).  All three allocate an 80-byte
frame (`addi sp,sp,-80`), so the saves occupy `[-16,0)` and the body uses `[-80,-17)` only.

## Existing count-2 proofs (baseline, unchanged)

`RvProof.lean` generates `Gen.Rv{X1,ZbbX1,Crypto}P.{Base,D0..,P0..,Final}`: symbolic slices over
`Riscv.run` from `entryS 0`, cuts after every instruction that first produces an `A n r t` (and at
most 70 steps apart), needed location variables found backwards from the 64 output bytes of the
two-block run.  It covers exactly `count = 2` because the run is a single straight-line symbolic
run of 12613 steps; there is no induction over the loop.  (P-tree `Final.out_final` is still in
`Axioms.lean`; the every-count proofs below supersede it but the old tree is kept as the model
check shared with `rvcheck`.)

## Every-count proof (done)

### Generated loop trees (`RvLoop.lean`, `lake exe rvloop <kern> <dir> all`)

Per kernel, under `Hashtree/Gen/Rv*L/` (git-ignored, part of `Gen.tar.zst`):

* `Head.lean`: `Rhead := run prog pe M0 (fun _ => false) H (entryS 0)`, `KP := abstract Rhead`,
  `KP_mem : KP.mem = KPLog` (the 16 save cells, decided), `KH := { KP with mem := [], assume := [] }`,
  `KH_map : mapState e σ KP = fr (KP.mem.map ...) (mapState e σ KH)`, the `KH_len/vr/fl/nOnly/err/
  tail` facts, `head_addrs` (every head write is a save slot in `[-16,0)`), `SAVES_lo`, `saveOk`
  (the save log holds what the prologue stored; proved by computational `simp` with the concrete
  variable ids), `asmHead` (discharges the prologue's two no-wrap `slli` assumptions from
  `0 ≤ σ 2`, `32*σ 2 < 2^63`), and `slicePro` (the `H`-step slice check from `entryS 0` to `KP`).
* `It/Base.lean`, `It/P0..P{C-1}.lean`: symbolic slices of the iteration, cut after every
  instruction that first produces `A n r t`, at most 70 steps apart; each has `sliceCheck`,
  the `inv_*`/`core*` value lemmas and the transfer `tau*` hypotheses for the cut.
* `It/Final.lean`: `Rlast` (run of the last short slice: 52 steps from `K129` for x1, 42 steps
  from `K128` for zbb/crypto), `E0..E{C} := envAbs (E{i-1}) (run of slice i)`, `KF := K{C}`,
  `EF := E{C}`, `inv_final`/`out_final`/`log_final` for the last block, `KF_eq : K{C} = abstract
  Rlast`, `KF_cutok`, `tauE`, `KF_live : gprLiveRel Rlast KH tauE = true`, and the
  `KF_pc/halted/err/tail/vr/flags` facts.  `C = 130` (x1), `C = 129` (zbb/crypto).
* `T0/Base.lean`, `T0/P0.lean`, `T0/Final.lean`: the exit segment (6 steps x1/zbb, 5 crypto)
  from `KH`; its symbolic memory `M0T := mem0sT 10 11 rodata gotT SAVES` reads the two (one)
  save slots back as memory keys at `[-16,-8)`, `[-8,0)`, so the epilogue's loads are symbolic;
  `run_final` (hypothesis `σ 2 = 0`) gives `run ... NS (mapState e σ KH) = mapState (E1 e) σ K1`,
  plus `KF_halted/err/tail/mem`.

`tauE` (emitted in the `It` namespace) is
`[(⟨64, [1]⟩ : Lin), (⟨32, [0, 1]⟩ : Lin), (⟨-1, [0, 0, 1]⟩ : Lin)]`, i.e.
`sigmaOf tauE σ = [64 + σ 0, 32 + σ 1, -1 + σ 2, ...]` (input pointer + 64, output pointer + 32,
count - 1).  Note this is *not* the x86 spelling `[a1+64, a0+32, a2-1]` with `Lin.ofInt`: the
`Lin` encoding carries the variable coefficients `[1]`, `[0,1]`, `[0,0,1]` and the proof files
must qualify it as `It.tauE` (it is declared inside the generated `It` namespace).

### `Hashtree/Proofs/RvAll.lean` (shared induction, unchanged in statement)

* `mem0sT ro got rodata gotT saves`: `mem0s` except that stack bytes at the prologue's save
  offsets are memory keys (`.dat (.var (.m rStack off)) ((off+16)%4)`), with
  `mem0sT_keyed` (in `RiscvSym.lean`) and `mem0RelT0` (the exit's `Mem0Rel` from `WfMemR` plus
  the accumulated save log).
* `rv_loop`: induction on the remaining count `j`.  Invariants: the frame log is in range,
  the first `k` output blocks are SHA-256 bytes, and the prologue's save slots still hold what
  the prologue stored.  The `succ` case: `run_fr` moves the log into the initial memory,
  `head_ecomb` starts the iteration at the loop head, `itRun` advances the body, `itReach`
  reopens the end cut at `KH` under `tauE` (`mapState_reached_vars`), and the induction
  hypothesis continues with `sigmaOf tauE σ`, count `j`, output pointer `σ 1 + 32*k`.

### Per-kernel final proof (e.g. `RvX1All.lean`, identical shape for zbb/crypto)

1. `steps`, `IT_eq : IT = It.NS`, `EX_eq : EX = T0.NS` (both `decide +kernel`).
2. `tau0/tau1/tau2 : sigmaOf It.tauE σ i = 64 + σ 0 / 32 + σ 1 / -1 + σ 2` (unfold
   `sigmaOf`/`tauAt`/`It.tauE`/`Lin.eval`/`dotC`, then `simp`).
3. `itReach`: `simp only [It.EF, It.KF]`, `rw [It.KF_eq]`, then `mapState_reached_vars` with
   `env := It.E{C-1} e`, `R := Rlast`, `cuts := It.KF_cutok`, `gprLiveRel_sound It.KF_live`,
   `KH_len`, the `KF_*` facts, `KH_vr/KH_fl/KH_mem`.  (`It.EF e` unfolds to
   `envAbs (It.E{C-1} e) Rlast`, which is what the theorem produces.)
4. `correct`: the head is one `rvSlice_sound` application (`proSlice`) from `entryS 0` to `KP`,
   with `asmHead` discharging the prologue's assumptions.  Its log `KP.mem` (mapped with
   `envAbs env0 Rhead`) gives the loop's initial `InRange 0`/`OutOk 0`, and `saveOk` gives the
   save-slot invariant (`rw [KP_mem]` to expose `KPLog`).  The final index is
   `H + (c * It.NS + T0.NS)` (`hidx`, an `omega` step over `IT_eq`/`EX_eq`); `hPr'` restates the
   prologue result with `Rhead` visible so `KH_map` can fire.  `rv_loop` is then applied with
   `itRun := It.run_final` (`Mem0Rel` from `simpa only [M0]`), `itReach`, `itOut := It.out_final`,
   `logLast := It.log_final`, and the exit tuple from `T0.run_final` (its halted/err/tail/mem
   facts transported through `mapState`).  Final `InRange (32*c)`/`OutOk c` by `simpa` over
   `Nat.mul_zero`/`Nat.zero_add`.

### Dispatcher stub (`Hashtree/Proofs/RvDispatch.lean`)

The shipped `hashtree_hash` is `auipc a5, .data.rel.local; ld a5, 0(a5); c.jr a5`.
`stub_correct`: from *any* LP64D entry state (every register a distinct location variable) on
any memory whose `.data.rel.local` slot (region 60, bytes `[0,8)`) holds a pointer to
`init_and_hash` (region 6), the three instructions halt after 3 steps with
`tail = some "init_and_hash"`, no model error, no recorded condition and no writes.
`cmem_rel` shows the hypothesis is satisfiable (a concrete memory with the slot pointer and zero
data elsewhere).  The dynamic-linker write of the slot is not modelled (it is the hypothesis
`Mem0Rel env σ M0 mem0c`).

### Dispatcher selection (`Hashtree/Proofs/RvDispatchInit.lean`)

`init_and_hash` and `hashtree_init` are proved functionally on concrete states, by finite
classes.  The concrete memory has the GOT slots pointing at the three kernel regions (12/15/18),
canary bytes `0x5a`, zero input/output buffers, and a `.data.rel.local` slot that starts at
`init_and_hash`; the `riscv_hwprobe` call is answered by the harness's `syscallStub`, and the run
continues from the call's return point, exactly as `runChain` does.

* `ih_call_syscall`/`hi_call_syscall` — the prologue reaches `tail = some "call:syscall"` with
  the harness's ABI (25 steps for `init_and_hash`, 19 for the NULL path of `hashtree_init`).
* four outcome theorems: `ih_syscall_fail_x1` (syscall fails -> `x1`), `ih_probe_crypto`
  (`(v &&& 0x2100) = 0x2100`), `ih_probe_zbb` (`(v &&& 16) ≠ 0`), `ih_probe_x1` (successful
  probe with neither bit set).  Each shows the run halts with `tail = some <kernel>`, `err = none`
  (so the stack-canary check took the pass branch), and the kernel pointer written into the
  `.data.rel.local` slot.
* `ih_select_bits`/`hi_select_bits` — the 8 combinations of the three tested bits
  (`b13 b8 b4 : Bool`, `probeOf`), with the kernel chosen by `selName`/`selRegion`;
  `init_and_hash` tail-calls it, `hashtree_init` returns normally (`tail = none`) after installing
  it.  `classOfNat_ext` proves that the mask `0x2110` (the three tested bits) determines the class,
  and `selName_eq_classOf`/`selRegion_eq_classRegionNat` classify the 8 combinations.
* `hi_override` — `hashtree_init(k)` for `k` one of the kernel regions (non-NULL): the argument
  pointer is written into the slot, the canary check passes, and the function returns to `ra`.

A general "for every probe answer" theorem over a symbolic probe value is **not expressible** in
the current RV64 model: `Riscv.exec`'s branch needs `Ctl.asConst` for the condition lanes
(`ctlOf` only builds constants, and a symbolic `Int` comparison under `Cond.decideC` is stuck
rather than `none`), so a symbolic `hwprobe` result cannot select a branch.  The finite-class
theorems plus the mask lemma cover every probe answer up to the three tested bits; the rest of
the model (the dispatcher's slot write, the canary check, the syscall ABI) is proved, not tested.

### Register preservation (`Hashtree/Proofs/RvRegs.lean`)

LP64D requires `ra`, `sp` and `s0`-`s11` to be unchanged across a call.  The kernels write only
temporaries plus `sp` (frame) and `s9`/`s10` (saved in the prologue, restored in the exit).

**Static tier (proved).**  An instruction that does not name `r` as its destination cannot change
`getG r` (`exec_gpr`), and if no instruction of the program names `r` then *every* run preserves
`r` (`run_gpr`, by induction on the fuel; the fetch is tied to the `.all` check through
`Array.getElem?_eq_some_iff`/`Array.mem_iff_getElem`).  `PRESERVED = [x1, x8, x9, x18..x24, x27]`
(`ra`, `s0`-`s8`, `s11`) is checked instruction-by-instruction against each generated program by
`all_x1`/`all_zbb`/`all_crypto` (`decide +kernel`), giving

    correct_regs_x1/zbb/crypto : fin.getG r = (mapState env0 σ (entryS 0)).getG r   (r ∈ PRESERVED)

for every count, memory and branch-oracle.  These theorems have only the standard Lean axioms
(`all_*` have none at all).

**Saved registers (`sp` proved, `s9`/`s10` blocked).**  These three registers *are* written, so
`exec_gpr` does not apply; the argument goes through the save slots (`sd 25/sd 26` in the
prologue, `ld` in the exit), visible after the loop decomposition.  `rv_loop`
(`Proofs/RvAll.lean`) now carries this as a dynamic fact:

* `(PRES : List Nat) (ENTRY : State E Lin)` and the hypothesis
  `entrySt : ∀ (e) (σ' : Nat → Int) (r : Nat), r ∈ PRES →
      (mapState (EF e) (sigmaOf tauE σ') ENTRY).getG r = (mapState e σ' ENTRY).getG r`;
* the per-iteration composition hypothesis `entryComb : ∀ e σ₁ σ₂ σ₃ m r, r ∈ PRES →
      (mapState (ecomb e σ₁ m) σ₂ ENTRY).getG r = (mapState e σ₃ ENTRY).getG r`
  (needed because the loop body's environment is `ecomb e σ' (view M mem0c)`, which is not
  definitionally equal to `e` even at a literal register index);
* the exit hypothesis `t0Res` returns, with its final state `S`, the clause
  `∀ r ∈ PRES, S.getG r = (mapState e σ' ENTRY).getG r`;
* the conclusion gains `∀ r ∈ PRES, fin.getG r = (mapState e σ' ENTRY).getG r` (the `zero` case
  is `t0Res`'s clause with `fr` leaving `gpr` untouched plus `entryComb`; the `succ` case chains
  the induction hypothesis with `entrySt` and `entryComb`).

Each kernel's `correct` instantiates `ENTRY = entryS 0` and proves the exit clause from
`T0.run_final` + `T0.K1`'s concrete gpr lane (`getG 2 = .ptr ⟨rStack, 0⟩`) + `envAbs`/`Rhead`
identifying `mapState (envAbs env0 Rhead) σ (entryS 0)` with `mapState env0 σ (entryS 0)` (for
`r = 2` both are `.ptr ⟨rStack, 0⟩`).  **Status (2026-11-13): implemented with `PRES = [2]`**
(`sp`: proved dynamically; the three `correct` theorems above gained the clause; 144 insertions,
15 deletions over the four proof files).

**Why `PRES = [2, 25, 26]` does not typecheck.**  For `r = 25`/`26` the entry state's lanes are
`.num (.var (.n 50)) (.var (.n 51))`, so `entrySt` reduces to `EF e (.n i) = e (.n i)`; after
`getG_hom` the goal is `mapVal (EF e) σ (.num …) = mapVal e σ (.num …)`, i.e. exactly
`(EF e) (.n 50) = e (.n 50)`.  This is false definitionally at every point of the generated
environment chain: `EF = envAbs (E129 env0) Rlast` and each `E_j = envAbs (E_{j-1} env0)
(run … K_{j-1})` looks up `R.gpr[25]?` for `.n 50`, but the iteration-end states use `s9`/`s10`
as scratch (`E4`'s `gpr[25]` is already a scratch expression such as
`.num (.and (.var (.n 60)) (.var (.n 34)) …)`), so the chain does not collapse to `e`.  Measured
on the VM: `example (e) : It.E1 e (.n 50) = e (.n 50) := by rfl` already fails (not definitionally
equal), and the full `entrySt` at `r = 25` fails fast with `maximum recursion depth has been
reached` (default limits) or `(deterministic) timeout at whnf` after unfolding the entry
(`maxRecDepth 2000000`, `maxHeartbeats 200000`: 14.6 s to the timeout; the direct `rfl` route
also exceeds the heartbeat budget).  A genuine dynamic `s9`/`s10` theorem needs the save/restore
argument through the memory-keyed frame log (`Mem0Rel` at the exit) — a semantic argument, not a
reduction; it is reported here as the failing invariant, per the review instruction.

`ra`, `sp` and the `s0`-`s11` state are what LP64D requires; the `ra` part and the untouched ten
registers are the `correct_regs_*` theorems above.

## Chain composition: wrapper -> `hashtree_hash` -> `init_and_hash` -> kernel -> return -> epilogue

`wrapper_end2end` (`RvWrapperLinux.lean`) left the post-return state as the explicit `returned s`.
`Hashtree/Proofs/RvChain.lean` replaces that statement-level assumption with a composition
mirroring the x86-64 `Hashtree.Proofs.X86Chain`, on one shared memory:

* **Framework.**  `Link` (tail-call name, program, own code/rodata region, steps, step function),
  `Spec` (link + `pre`/`post`), `resume` (the state handed to a tail-called image: `pc = 0`,
  halt/tail flags cleared, same memory/registers), `chainRun` (runs the links in order, following
  `tail = some <next name>` and stopping on a return/tail mismatch), `KSpecC` (per-link obligation:
  a return meets its post, a tail names the next link and hands it a state meeting its pre),
  `ChainPost`/`FirstPre`, and `chain_sound` (induction on the list: under `KSpecC` the chain
  returns with `err = none`, `tail = none` and the returning link's post-condition).
* **The `ret` boundary.**  `return_transition`: a callee run ending `halted = true`,
  `tail = none`, `err = none` resumes the caller as `returned s` — `halted = false`, `tail = none`,
  `pc = 8` (`retPc`), `err = none`, with `mem`, `gpr` and every `getG r` unchanged.  This lemma is
  the explicit, proved statement of what the model-level cross-image transfer preserves.
* **The concrete chain.**  One closed shared memory `chainMem` (the wrapper's stack and
  `.data.rel.local` slot, the dispatcher's own regions, the kernel's rodata/GOT/input map).  Stages:
  `wrapStep` (8 steps to `CALL hashtree_hash`), `stubStep` (3 steps, tail `init_and_hash`),
  `dispAStep` (25 steps, tail `call:syscall`), `sysStep` (the harness `riscv_hwprobe` answer),
  `dispBStep` (34 steps from the return point, tail the selected kernel), and the per-class
  `kerRun` (the kernel's own `correct` theorem on its model memory).  `resume` is applied exactly
  once, at each tail boundary, and every canonical state is defined from the resumed predecessor
  (`t1 := stubStep (resume w1)`, `d1 := dispAStep (resume t1)`, `s1 p := sysStep p (resume d1)`,
  `d2 p := dispBStep (s1 p)`), so each pre/post obligation is a syntactic `rfl`/projection.  Both
  details are load-bearing in practice: resuming *inside* a stage function made the defeq check
  re-evaluate the previous image and fail with "maximum recursion depth reached", and the memory
  argument of a run must be a closed definition for `rfl` to evaluate it (measured: ≈1 s per
  closed kernel run; open memory arguments diverge or exceed the recursion limit).
* **Links and soundness.**  `link_wrapper`/`link_stub`/`link_dispA`/`link_d2_none|zbb|crypto`
  discharge the per-link facts; `specs` is the five-link list (wrapper 8 steps, `call:hashtree_hash`
  3, `init_and_hash` 25, `call:syscall` 59, kernel `ksteps p c`); `specs_KSpecC_none|zbb|crypto`
  prove `KSpecC`; `chainRun_none|zbb|crypto` prove `chainRun mm specs entryChain = kerRun ...` by
  `rfl`; `chain_sound_*` instantiate `chain_sound`, and `chain_none|zbb|crypto` give the kernel's
  halt/err/tail, its dynamic `sp` and its `InRange`/`OutOk` output facts as the chain's
  post-condition — all derived from `Rv{X1,ZbbX1,Crypto}L.correct`, not assumed.
* **Return into the wrapper.**  `postMem p c env0 σ kMem orcK :=
  view (kerRun ...).mem (view (d2 p).mem chainMem)` replays the kernel's write log over the Go-side
  memory; `sret := returned (kerRun ...)`.  `ra_slot_post` **derives** the wrapper's `ra` slot
  (`loadVal (postMem ...) (sret ...) ⟨rStack,0⟩ = .ok (.ptr ⟨rRet,0⟩)`) from the kernel's
  `InRange` via the new `readCell`/`pbRest`/`loadLane`/`loadVal` extensionality lemmas
  (`inRange_ne_slot`: no kernel write lands in the eight `ra` bytes), with `ra_slot_go_*` the
  closed `rfl` checks that the Go-side log does leave the pointer there.  `end2end_of` and
  `end2end_none|zbb|crypto` then run the wrapper's epilogue (`wrapper_epilogue`, 3 steps) on
  `postMem`/`sret` and conclude `halted = true`, `tail = none`, `err = none`, `ra = ⟨rRet,0⟩`,
  `sp = ⟨rStack,8⟩`, plus the kernel's `InRange`/`OutOk` — the wrapper's post-return state is
  derived from the callee run.  `kerRun_len` supplies the register-file length the epilogue's
  `ld ra` needs.

**Still model-level** (stated at the link boundaries, not derived from a `Riscv.run`):
1. the `resume`/`returned` transfer itself (`return_transition` is a lemma about the boundary, not
   an `exec` step; a `ret`/`jalr` into another image is not representable in `Riscv.run`);
2. the `riscv_hwprobe` answer, which is the harness `syscallStub` (a link that is not a program);
3. the ABI register hand-off at the kernel entry: the kernel starts at the declared LP64D entry
   with the constants the wrapper passed (`cOut`, `cIn`, `3`, proved at link 1), but the
   dispatcher's restore of `a0`-`a2` from `s3`/`s2`/`s1` is not mechanized (`State.getG` on a
   concrete run state whose registers are written by `List.set` does not reduce); the
   dispatcher's own selection/canary facts are proved separately in `RvDispatchInit`;
4. the kernel's own address space `kMem`: only its write log is replayed into `postMem`; its read
   hypotheses (`WfMemR`, `hin`) are the kernel model's, not the Go memory's.

The finite-probe limitation is unchanged: the chain is instantiated per tested probe class
(`none`/`0`, `0x10`, `0x2100`, and the 8 `ih_select_bits` combinations), because a symbolic
`hwprobe` value is not expressible in the model (`Ctl.asConst` on a register value).

## Remaining gaps

* Register preservation: `ra`, `s0`-`s8`, `s11` are proved by `correct_regs_*` (dynamic static
  argument); `sp` is proved dynamically by the `rv_loop` `PRES = [2]` clause (see above).
  `s9`/`s10` are still not exposed: `PRES = [2, 25, 26]` does not typecheck definitionally
  (the env chain rebinds the positional lanes; evidence in the saved-registers section).
* The Go wrapper's *return path from the callee*: `RvWrapperLinux.lean` proves the prefix
  (arguments in `a0`-`a2`, link and B7-correct callee `sp`), the `hashtree_hash` tail call, and
  the epilogue; `RvChain.lean` now composes those with the dispatcher and the selected kernel for
  each finite probe class and derives the wrapper's post-return state from the callee run
  (`end2end_*`).  What remains at the model level is the transfer itself: a `ret` from another
  image is not a step of `Riscv.run`, so the boundary is the proved lemma `return_transition`
  (`returned s`: `pc := 8`, same registers/memory, cleared flags) rather than a single
  `Riscv.run` over a linked image.  The ABI restore of `a0`-`a2` at the kernel entry is likewise
  stated, not mechanized (`State.getG` on `List.set`-written concrete registers does not reduce);
  the stack-check preamble is abstracted (as in the kernel model).
* The dispatcher's dynamic selection over a *symbolic* probe value: see the model limitation
  above.  What is proved is `RvDispatchInit` (the finite classes plus the mask lemma for every
  probe answer up to the three tested bits).  `rvcheck` additionally validates the linked runs
  with the real kernels for the probe classes below.
* `Gen.tar.zst`/`proofs.json` were not repacked (`make pack` is the integrator's job).  The
  generated `Rv*L` trees are git-ignored; the checked-in generator (`RvLoop.lean`) emits them
  (including `tauE`).  The three `It/Final.lean` files in the current on-disk tree were
  hand-patched with the same `tauE` definition before the generator gained it; a fresh
  `lake exe rvloop <k> Gen all` reproduces them.
* `lake exe rvcheck` validates the models for 140 runs per kernel (counts and unaligned
  layouts), the dispatch stub and the `hashtree_init` xor-canary path, and the `sp` alignment
  layouts; it is concrete testing, not a proof.

## Validation of the reopening design (runtime, `RvShapeTmp2.lean`, exploratory)
