# R4: linux/riscv64 machine-code proofs

Status log: `results/r4-riscv-log.md` on the control machine.  Branch `research/formal-r4-riscv`
based on `research/formal-verification` (0a724af).  Lean 4.35.0, all builds on VM2.

## Contract (what the three kernels are proved to do)

The three RV64 kernels (`hashtree_sha256_riscv_x1`, `..._zbb_x1`, `..._crypto`) implement

    void hashtree_hash(const void *out, const void *in, size_t count)

in the LP64D calling convention: `a0 = out`, `a1 = in`, `a2 = count`, `ra` = return address,
`sp` = stack.  `count` is the number of 64-byte input blocks.  For every `count` the kernel
writes `32*count` output bytes; output byte `32*n + j` is byte `j` of
`SHA-256(pad(block n))`, where `pad` is the fixed padding block (the kernel hashes every 64-byte
block independently, starting from the same `.LDIGEST` constants, with the precomputed padding
words at `.LPADDING`; this is exactly `Hashtree.Spec.blk inp n`).

Formally (one theorem per kernel, `Hashtree/Proofs/Rv{X1,ZbbX1,Crypto}All.lean`):

    theorem correct (c : Nat) (inp : Nat → Byte) (env0 : Key → W32) (σ : Nat → Int)
        (mem0c : Addr Int → Cell W32 Int) (orcC : Nat → Bool)
        (hw : WfMemR 10 11 rodata gotT mem0c) (he : X86Sym.EnvMem env0 σ mem0c)
        (hc : σ 2 = c) (hσ0 : 0 ≤ σ 2) (hb : 32 * σ 2 < 2 ^ 63)
        (hin : ∀ o : Nat, mem0c ⟨rIn, σ 0 + o⟩ = .dat ((inp o).zeroExtend 32) 0) :
        let fin := Riscv.run prog pe mem0c orcC (steps c) (mapState env0 σ (entryS 0))
        fin.halted = true ∧ fin.err = none ∧ fin.tail = none ∧
          InRange (σ 1) (32 * c) fin.mem ∧ OutOk inp (σ 1) c fin.mem

with `steps c = H + c * IT + EX` (13 + 6300*c, 13 + 4140*c, 11 + 2732*c).  `InRange` says every
logged write is either one of the `32*c` output bytes or a byte of the kernel's own frame;
`OutOk` says output byte `32*n + 4*i + b` is byte `4*i + b` of `blk inp n`.  The entry state
`entryS 0` sets `ra` to the return region, `sp` to the symbolic stack pointer, and every other
register to a location variable; `count` is the symbolic integer `σ 2`.

What the theorem does **not** state (see "Remaining gaps"): register preservation (only memory
and output are constrained), the Go wrapper's `sp = 8 (mod 16)` invariant (B7) and its `$0-24`
frame, the dynamic-linker/constructor initialization of the dispatcher, and a symbolic
`hwprobe`-driven kernel selection.

Steps (model instruction count), measured from the generated programs (2026-11-12):

| kernel | len | loop head `H` | head | iteration | exit | `steps(c)` |
|---|---|---|---|---|---|---|
| `x1` | 6312 | 7 | 7 | 6300 | 6 | `13 + 6300*c` |
| `zbb_x1` | 4152 | 7 | 7 | 4140 | 6 | `13 + 4140*c` |
| `crypto` | 2742 | 6 | 6 | 2732 | 5 | `11 + 2732*c` |

Segment meanings: **head** = prologue `pc0..H` (ends at the loop head); **iteration** =
`H` (branch to the body taken) plus the body `H+2..L` ending with `jal 0,H` back to `H`, i.e.
`L - H` steps returning to `H` (`x1`: `7 -> 9..6307 -> 7`, `6307 - 7 = 6300`); **exit** = `H`
(branch not taken when `a0 = a2`) plus `H+1` (`jal 0,epilogue`) and the epilogue.
Bodies end with `addi a0,a0,32; jal 0,H`; all three kernels have identical data bodies
except the byte-swap of the two output words holding the length/counter (`slliw`/`lui`/`and`/`or`
for x1, `rev8`/`srai` for zbb_x1 and crypto).

Prologue/epilogue save slots: `x1` and `zbb_x1` save `s9,s10` (`sd 26,64(sp); sd 25,72(sp)`) and
restore them in the exit; `crypto` saves only `s9` (`sd 26,64(sp)`).  All three allocate an 80-byte
frame (`addi sp,sp,-80`), so the saves occupy `[-16,0)` and the body uses `[-80,-17)` only.

## Existing count-2 proofs (baseline, unchanged)

`RvProof.lean` generates `Gen.Rv{X1,ZbbX1,Crypto}P.{Base,D0..,P0..,Final}`: symbolic slices over
`Riscv.run` from `entryS 0`, cuts after every instruction that first produces an `A n r t` (and at
most 70 steps apart), needed location variables found backwards from the 64 output bytes of the
two-block run.  It covers exactly `count = 2` because the run is a single straight-line symbolic
run of 12613 steps; there is no induction over the loop.  (P-tree `Final.out_final` is still in
`Axioms.lean`; the every-count proofs below supersede it but the old tree is kept as the model
check shared with `rvcheck`.)

## Every-count proof (done)

### Generated loop trees (`RvLoop.lean`, `lake exe rvloop <kern> <dir> all`)

Per kernel, under `Hashtree/Gen/Rv*L/` (git-ignored, part of `Gen.tar.zst`):

* `Head.lean`: `Rhead := run prog pe M0 (fun _ => false) H (entryS 0)`, `KP := abstract Rhead`,
  `KP_mem : KP.mem = KPLog` (the 16 save cells, decided), `KH := { KP with mem := [], assume := [] }`,
  `KH_map : mapState e σ KP = fr (KP.mem.map ...) (mapState e σ KH)`, the `KH_len/vr/fl/nOnly/err/
  tail` facts, `head_addrs` (every head write is a save slot in `[-16,0)`), `SAVES_lo`, `saveOk`
  (the save log holds what the prologue stored; proved by computational `simp` with the concrete
  variable ids), `asmHead` (discharges the prologue's two no-wrap `slli` assumptions from
  `0 ≤ σ 2`, `32*σ 2 < 2^63`), and `slicePro` (the `H`-step slice check from `entryS 0` to `KP`).
* `It/Base.lean`, `It/P0..P{C-1}.lean`: symbolic slices of the iteration, cut after every
  instruction that first produces `A n r t`, at most 70 steps apart; each has `sliceCheck`,
  the `inv_*`/`core*` value lemmas and the transfer `tau*` hypotheses for the cut.
* `It/Final.lean`: `Rlast` (run of the last short slice: 52 steps from `K129` for x1, 42 steps
  from `K128` for zbb/crypto), `E0..E{C} := envAbs (E{i-1}) (run of slice i)`, `KF := K{C}`,
  `EF := E{C}`, `inv_final`/`out_final`/`log_final` for the last block, `KF_eq : K{C} = abstract
  Rlast`, `KF_cutok`, `tauE`, `KF_live : gprLiveRel Rlast KH tauE = true`, and the
  `KF_pc/halted/err/tail/vr/flags` facts.  `C = 130` (x1), `C = 129` (zbb/crypto).
* `T0/Base.lean`, `T0/P0.lean`, `T0/Final.lean`: the exit segment (6 steps x1/zbb, 5 crypto)
  from `KH`; its symbolic memory `M0T := mem0sT 10 11 rodata gotT SAVES` reads the two (one)
  save slots back as memory keys at `[-16,-8)`, `[-8,0)`, so the epilogue's loads are symbolic;
  `run_final` (hypothesis `σ 2 = 0`) gives `run ... NS (mapState e σ KH) = mapState (E1 e) σ K1`,
  plus `KF_halted/err/tail/mem`.

`tauE` (emitted in the `It` namespace) is
`[(⟨64, [1]⟩ : Lin), (⟨32, [0, 1]⟩ : Lin), (⟨-1, [0, 0, 1]⟩ : Lin)]`, i.e.
`sigmaOf tauE σ = [64 + σ 0, 32 + σ 1, -1 + σ 2, ...]` (input pointer + 64, output pointer + 32,
count - 1).  Note this is *not* the x86 spelling `[a1+64, a0+32, a2-1]` with `Lin.ofInt`: the
`Lin` encoding carries the variable coefficients `[1]`, `[0,1]`, `[0,0,1]` and the proof files
must qualify it as `It.tauE` (it is declared inside the generated `It` namespace).

### `Hashtree/Proofs/RvAll.lean` (shared induction, unchanged in statement)

* `mem0sT ro got rodata gotT saves`: `mem0s` except that stack bytes at the prologue's save
  offsets are memory keys (`.dat (.var (.m rStack off)) ((off+16)%4)`), with
  `mem0sT_keyed` (in `RiscvSym.lean`) and `mem0RelT0` (the exit's `Mem0Rel` from `WfMemR` plus
  the accumulated save log).
* `rv_loop`: induction on the remaining count `j`.  Invariants: the frame log is in range,
  the first `k` output blocks are SHA-256 bytes, and the prologue's save slots still hold what
  the prologue stored.  The `succ` case: `run_fr` moves the log into the initial memory,
  `head_ecomb` starts the iteration at the loop head, `itRun` advances the body, `itReach`
  reopens the end cut at `KH` under `tauE` (`mapState_reached_vars`), and the induction
  hypothesis continues with `sigmaOf tauE σ`, count `j`, output pointer `σ 1 + 32*k`.

### Per-kernel final proof (e.g. `RvX1All.lean`, identical shape for zbb/crypto)

1. `steps`, `IT_eq : IT = It.NS`, `EX_eq : EX = T0.NS` (both `decide +kernel`).
2. `tau0/tau1/tau2 : sigmaOf It.tauE σ i = 64 + σ 0 / 32 + σ 1 / -1 + σ 2` (unfold
   `sigmaOf`/`tauAt`/`It.tauE`/`Lin.eval`/`dotC`, then `simp`).
3. `itReach`: `simp only [It.EF, It.KF]`, `rw [It.KF_eq]`, then `mapState_reached_vars` with
   `env := It.E{C-1} e`, `R := Rlast`, `cuts := It.KF_cutok`, `gprLiveRel_sound It.KF_live`,
   `KH_len`, the `KF_*` facts, `KH_vr/KH_fl/KH_mem`.  (`It.EF e` unfolds to
   `envAbs (It.E{C-1} e) Rlast`, which is what the theorem produces.)
4. `correct`: the head is one `rvSlice_sound` application (`proSlice`) from `entryS 0` to `KP`,
   with `asmHead` discharging the prologue's assumptions.  Its log `KP.mem` (mapped with
   `envAbs env0 Rhead`) gives the loop's initial `InRange 0`/`OutOk 0`, and `saveOk` gives the
   save-slot invariant (`rw [KP_mem]` to expose `KPLog`).  The final index is
   `H + (c * It.NS + T0.NS)` (`hidx`, an `omega` step over `IT_eq`/`EX_eq`); `hPr'` restates the
   prologue result with `Rhead` visible so `KH_map` can fire.  `rv_loop` is then applied with
   `itRun := It.run_final` (`Mem0Rel` from `simpa only [M0]`), `itReach`, `itOut := It.out_final`,
   `logLast := It.log_final`, and the exit tuple from `T0.run_final` (its halted/err/tail/mem
   facts transported through `mapState`).  Final `InRange (32*c)`/`OutOk c` by `simpa` over
   `Nat.mul_zero`/`Nat.zero_add`.

### Dispatcher stub (`Hashtree/Proofs/RvDispatch.lean`)

The shipped `hashtree_hash` is `auipc a5, .data.rel.local; ld a5, 0(a5); c.jr a5`.
`stub_correct`: from *any* LP64D entry state (every register a distinct location variable) on
any memory whose `.data.rel.local` slot (region 60, bytes `[0,8)`) holds a pointer to
`init_and_hash` (region 6), the three instructions halt after 3 steps with
`tail = some "init_and_hash"`, no model error, no recorded condition and no writes.
`cmem_rel` shows the hypothesis is satisfiable (a concrete memory with the slot pointer and zero
data elsewhere).  The dynamic-linker write of the slot is not modelled (it is the hypothesis
`Mem0Rel env σ M0 mem0c`).

The general "for every probe answer, the dispatcher tail-calls the right kernel" statement is
**not expressible** in the current RV64 model: `Riscv.exec`'s branch needs `Ctl.asConst` for the
condition lanes (`ctlOf` only builds constants, and a symbolic `Int` comparison under
`Cond.decideC` is stuck rather than `none`), so a symbolic `hwprobe` result cannot select a
branch.  The selection is instead validated concretely by `lake exe rvcheck` (see below);
the derived rule from the `init_and_hash` disassembly is: syscall fails -> x1; `(v & 0x2100) =
0x2100` -> crypto; else `(v & 16) != 0` -> zbb; else x1.

## Proved vs assumed

Proved (no `sorry`; axiom audit below):

* `Hashtree.Proofs.RvX1L.correct` — `hashtree_sha256_riscv_x1` for every count.
* `Hashtree.Proofs.RvZbbX1L.correct` — `hashtree_sha256_riscv_zbb_x1` for every count.
* `Hashtree.Proofs.RvCryptoL.correct` — `hashtree_sha256_riscv_crypto` for every count.
* `Hashtree.Proofs.RvDispatch.stub_correct` — the `hashtree_hash` PLT stub tail-calls
  `init_and_hash` from any registers; `Hashtree.Proofs.RvDispatch.cmem_rel` — its memory
  hypothesis is satisfiable.
* Infrastructure: `Hashtree.Asm.gprLiveRel_sound`, `gpr_map_live`, `mapState_reached_vars`,
  `sigmaOf_nil` (`RiscvReach.lean`); `Hashtree.Proofs.Rv.rv_loop`, `mem0RelT0`, `mem0sT_keyed`
  (`RvAll.lean` / `RiscvSym.lean`); the generated `sliceCheck`s, `KF_eq`, `KF_live`, `KH_map`,
  `KP_mem`, `head_addrs`, `saveOk`, `asmHead`, `run_final`, `out_final`, `log_final` per kernel
  (`decide`/`decide +kernel` over the symbolic programs).

Axiom audit (`/tmp/R4Axioms.lean`, since a full `Axioms.lean` run needs the x86/ARM proofs built;
the same lines are in `Axioms.lean` under `/- R4: riscv64 -/`): all five theorems depend only on
`propext`, `Classical.choice`, `Quot.sound` plus the per-lemma
`..._native.bv_decide.ax_*` axioms of the generated cores (the proof checker runs compiled
`bv_decide`, as documented at the top of `Axioms.lean`).  No `sorryAx`.

Assumed (not proved here):

* The memory shape hypotheses: `WfMemR` (rodata bytes, GOT pointer entries, input bytes,
  everything else poison and never read), `EnvMem`, and `hin` (input buffer contents).  The
  theorem is quantified over every concrete memory satisfying them; `cmemR_wf`/`hyps_satR` in
  `RiscvSym.lean` show they are satisfiable.
* The RV64 machine model itself (`Hashtree.Asm.Riscv.exec/run`), the same model the count-2
  proofs and `rvcheck` use.
* `count` range: `0 ≤ σ 2` and `32 * σ 2 < 2^63` (the prologue's `slli a2,a2,5` records no-wrap
  conditions; the theorem takes them as hypotheses and `asmHead` discharges them from the
  model's recorded assumptions).

## Remaining gaps

* Register preservation (`s9`,`s10` callee-save) is not stated by `correct`: the loop head's
  `GprLive` invariant keeps them consistent internally and `CutOk`/`REG` checks cover the cuts,
  but the final theorem exposes no `gpr` fact.  A separate statement would need the entry
  registers' values threaded through `rv_loop` (not done).
* B7 (`sp = 8 (mod 16)` at the Go->asm boundary) and the Go wrapper's `$0-24` argument frame are
  not modelled: `Hashtree/Kernels` has no riscv wrapper model (`Arm`, `ArmMac`, `X86`, `X86Win`
  only), so they cannot be connected to a proved kernel theorem.  The kernels themselves take a
  symbolic `sp` (`entryS 0`) and make no alignment assumption; `rvcheck` exercises the aligned
  and unaligned layouts (`sp = 8 mod 16: 48 runs done`).
* The dispatcher's dynamic selection: see the model limitation above.  `init_and_hash` and
  `hashtree_init` themselves are validated by `rvcheck` (probe classes below) but have no
  functional proof.
* `Gen.tar.zst`/`proofs.json` were not repacked (`make pack` is the integrator's job).  The
  generated `Rv*L` trees are git-ignored; the checked-in generator (`RvLoop.lean`) emits them
  (including `tauE`).  The three `It/Final.lean` files in the current on-disk tree were
  hand-patched with the same `tauE` definition before the generator gained it; a fresh
  `lake exe rvloop <k> Gen all` reproduces them.
* `lake exe rvcheck` validates the models for 140 runs per kernel (counts and unaligned
  layouts), the dispatch stub and the `hashtree_init` xor-canary path, and the `sp` alignment
  layouts; it is concrete testing, not a proof.

## Validation of the reopening design (runtime, `RvShapeTmp2.lean`, exploratory)

For all three kernels, with the kernel's own head length, loop head `H` and iteration length, and
`tauE` as above, the symbolic run over `mem0s 10 11 rodata gotPtrs` gives: `err = none`,
`gprLiveRel KF KH tauE = true`, `gprLiveRel Rhead KH [] = true`, all `KH` registers are pointer
or own-variable, `vr`/`flags` empty, `CutOk` true for `KF` and `Rhead`, and
`pc`/`halted`/`err`/`tail` equal to `KH`.  x1: 6300 steps / 320-frame cells; zbb_x1: 4140 steps;
crypto: 2732 steps.  (The x86-style `KF_shape` equality is false for all three; the body leaves
constants in dead registers, e.g. x1 `gpr14 lo = 0x00ff0000`/`hi = 0`, `gpr16 lo = 0x0000ff00`,
`gpr25 hi = 0`.)
